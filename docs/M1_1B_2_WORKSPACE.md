基于 main `a855b31`，合并后的 CI 已通过。本阶段仅实现 React 工作台及组件测试；沿用 M1-1B-1 的 HTTP 合同，不接入 AI，不修改 prototype 或 Pages。M1-1B-3 的完整自动化浏览器端到端及体验验收另开任务。

## 启动

本机 PostgreSQL 16 与 Python 3.12 已在前阶段配置，凭证仍在被 Git 忽略的 `apps/api/.env`。

```powershell
# 终端 1，apps/api
.venv/Scripts/python.exe -m app
# 终端 2，apps/web
npm ci
npm run dev
```

访问 http://localhost:5173。Vite 将 /api 代理到本机 8000。部署或分离开发可用 VITE_API_BASE_URL 指向 API；不得在该配置中写入令牌。开发期使用合成数据；关闭标签页后不保证恢复。

## 行为与边界

- 深色渐变、紫蓝重点色、卡片与宽屏双栏；窄屏按原始自述、补充输入、事实列表重排。标签、焦点、状态提示与删除确认均有可访问语义。
- 原始经历创建一次会话，不自动提取事实。新增事实先将用户的新陈述记录为补充回合，再引用该回合新增 pending 事实，不借用不支持该陈述的旧输入。
- 若补充回合已成功返回、事实新增失败，当前页面保留该回合 ID，重试复用它；不重复提交已确认成功的第一步。网络响应丢失时仍可能产生不确定写入，须先重新读取核对，API 尚无请求幂等键；页面不会自动重试写操作。
- 编辑、确认、拒绝、材料核实使用独立动作与 expected_version。编辑成功后关闭编辑框，待用户重新确认。编辑表单打开时禁止直接确认。
- 409 后读取最新资料，保留未保存输入，不重放写请求、不自动覆盖。若编辑版本改变，需用户明确复核最新版本后才能再次保存；材料核实采用相同规则。读取失败时暂禁写入，直至重新读取成功。
- 写成功但后续读取失败会明确提示“已保存”，禁止再次写入直至读取完成，避免把失败的显示刷新当作失败的保存。失效/不可访问会话移除旧显示，提供清除本页凭证入口，不暗中删除服务端数据。
- 来源展示使用 source_kind、source_change_id、source_turn_ids 和 original_source_turn_ids；原始自述与用户后续编辑分开，确认状态和全部变更历史可查。材料只记录引用和核实依据，明确是“用户提供材料并自行核实”，无上传或独立认证。
- 结束后只读，但仍可导出/删除。导出通过 Bearer fetch 下载 JSON Blob，不使用带凭证的链接；删除需明确点击确认，成功后清除页面及浏览器暂存。
- sessionStorage 的唯一应用条目是 pathwise.development.session，仅含 sessionId 与 token；不保存原始经历、事实、材料或历史。无 localStorage 持久化。浏览器暂存不可用时提示刷新恢复限制。
- lib/experience.ts 校验真实 JSON 响应合同，不直接信任未知返回。错误使用本地安全文案，不回显后端消息或敏感载荷。每次读取 no-store，凭证仅位于 Authorization 头。

## 验证

React Testing Library / user-event / jsdom / Vitest 覆盖创建与最小暂存、新增回合与失败重试、编辑后单独确认、当前来源与历史、409 输入保留和显式复核、冲突后读取失败的写入禁用、材料核实、拒绝、导出、刷新恢复、结束只读、删除确认和失效会话恢复；同时保留原健康检查客户端测试。

api-fixtures.json 是实际 FastAPI + 本机 PostgreSQL 返回的合成快照，录制会话已删除，真实令牌已替换为固定测试字符串。组件测试注入这些 HTTP 响应，并检查实际请求路径、Bearer、JSON 动作及版本；产品界面没有 Mock 开关或模拟资料。

本地前端 16 项测试通过，TypeScript/Vite 构建通过。另在真实浏览器中验证创建、补充事实、确认、编辑、再次确认、材料核实、来源历史、刷新恢复和结束只读；检查宽屏与窄屏布局。删除最终动作由组件测试和已有后端真实数据库测试覆盖。完整自动化 E2E 仍属于 M1-1B-3，不以本次手动检查替代。

package-lock.json 固定依赖，CI 改为 npm ci。构建有 Zod 依赖注释移除的非阻塞提示，不影响产物。PR 记录最终 CI 结果与已知限制。
