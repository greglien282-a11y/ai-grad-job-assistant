# M2.5 · 小范围产品研究准备

状态：**任务脚本和指标候选；没有招募或开展真实用户研究**。本轮只使用仓库公开合成案例和浏览器自动化，不上传真实简历，不记录真实参与者、满意度或节省分钟数。自动化测试用时不能充当人类任务用时。

## 研究要回答的问题

应届生能否从已有材料完成一个岗位草稿，知道建议为什么出现，并能发现没有证据的改写？使用同一材料制作第二岗位时，是否减少重复操作？打印和恢复是否可靠？这些问题与“模型是否格式正确”分开，也与 G4 写入安全准入分开。

首轮建议研究合成材料上的使用行为。真实资料、用户招募、录屏、研究人员访问、保存周期和删除请求均须独立同意；不因用户愿意试页面就默认为愿意上传简历或购买推理。生产页面依旧默认关闭，未部署，不提供本轮招募链接。

## 任务材料及分组

从冻结合成案例选择课程作业、无量化项目、团队限制、未部署 Python、计划 / 进行中 / 否定、夸大原文、双栏 PDF、表格 DOCX、中英文 Unicode、矛盾 JD 和双岗位材料。为对照保留每个文件、文本快照与案例 SHA。任何改变都生成新版本，不覆盖失败原件。

建议使用两套等难度合成材料，交叉安排“确定性基线”和“Mock 候选审核”顺序，减少练习效应。Mock 是已知示例，不代表真实模型表现。样本量、招募渠道、补偿、研究员及退出流程均尚未批准；此文不填写虚构人数或结果。

## 主持开场（未来研究时使用）

“今天测试软件，不评价你的求职能力。请只使用我们提供的合成材料。原文、用户草稿和平台认证是不同概念；本工具没有认证事实，AI 建议部分是离线规则 / Mock，没有真实模型。你可以跳过或停止，不需要提供联系方式、真实经历、账号或密钥。请说出你为什么做下一步；卡住也是有效发现。”

主持人先验证开发门禁、合成文件和无上传环境。记录帮助事件；不能代替用户完成后把任务记为独立成功。出现真实资料、意外网络外发、错误认证或意外写入时立即停止、保护证据并按 P0 处理，不继续收集。

## 可执行任务顺序

1. **首次导入**：给出合成 TXT / MD 或 PDF / DOCX，要求找到完整原文与解析警告。询问“引用位置指向哪里？”观察是否误认原文件字节坐标。
2. **结构核对**：找出一处预置顺序或分类问题并修正。核对元数据修改是否保留合法岗位；引用改变是否清楚提示影响与确认。
3. **第一岗位**：粘贴合成视觉算法 JD，辨认必备、加分、待核实及冲突条件。让用户说明哪些是 JD 原话、哪些是手工调整。
4. **经历关联**：选择、排序并说明一个字面相关条目，指出一个证据不足条目和一个明确能力缺口。不得暗示“Python”命中就证明部署熟练。
5. **候选审核**：展示原文、JD 引文及一个明确有风险的 Mock 改写，要求解释变化。观察是否发现新技能、数字、个人归属或计划变完成；不预先告诉答案。
6. **接受 / 拒绝 / 编辑**：要求拒绝无依据改写，查看拒绝状态；编辑一段临时审核文字并解释其未经认证。核对不能靠接受按钮、换 key 或新 Turn 解锁事实写入。
7. **岗位草稿**：把有来源的原句或用户自行负责的文字整理成草稿，对照原文核验；输出视图不能显示被阻断条目。
8. **排版与复习**：回答三题中的一题，再调整密度、模板和分页目标；回答应保留。改变真正的来源 / JD / 选用内容后，应重新核验失效状态。
9. **下载 / 恢复**：主动下载版本文件，先说明文件包含哪些个人资料，再刷新，确认没有隐式恢复；主动导入并逐项核对来源、两个岗位配置及复习状态。
10. **打印**：打开原生打印 / PDF，核对 A4、长段落、中英文换页、选择顺序和未认证自述标签；审查偏移、内部编号和风险候选不得混入简历正文。
11. **第二岗位**：同一材料建立后端或测试岗位，修改 JD、选用项与复习回答；切换两边检查互不污染，记录再次导入 / 重复填写情况。
12. **故障恢复**：使用未知合同、损坏引用或模拟不可用结果，观察用户是否理解“未应用 / 未保存”和下一步。不能把损坏候选部分显示为可用建议，不能自动回退真实网络调用。

每个任务结尾先问“你认为刚才保存到哪里？谁对内容真实性负责？”再提供解释，避免主持提示污染理解测量。涉及真实履历或完整拒绝历史的判断，不在本地原型中假定已获证明。

## 指标定义与手工记录

所有事件由未来获批观察员手工记录或在获批录屏中标注；本轮不新增遥测。

- **首次价值呈现时间**：从开始导入到用户首次准确解释一个有来源的岗位关联；首次看到任意建议不算成功。记录总经过时间、软件等待时间、主持帮助和中断，不能只挑最快样本。
- **第一岗位完成**：来源核对、条目整理、明确用户草稿、打印和保存全部完成。记录用时、有效操作数、回退数、重复输入、帮助次数；部分完成单独列出。
- **第二岗位重复成本**：在相同材料、可比任务下比较再次输入原文、JD、资料和来源核对次数。内容不同造成的必要劳动单列；不从一次合成自动化推算节省百分比。
- **建议依据理解**：用户能否指到原文和 JD 引文，解释字面关联与语义 / 熟练度差别，并区分规则、Mock 和自己编辑。每项独立记录正确、错误、需提示或无法判断。
- **错误改写识别**：预先封存具体风险和正确理由，记录发现 / 漏掉 / 误报及对应来源。分别统计新增技能、数字、部署、学历、团队责任、计划 / 否定和拒绝复活，不用一个平均值掩盖严重错误。
- **打印成功**：目标条目和顺序完整、阻断项不出现、无截断或多余内部信息；一页目标不强求删减真实内容。记录页数、布局问题及用户能否发现。
- **恢复成功**：严格解析后源图、岗位独立配置、条目、草稿和允许恢复的复习状态逐项一致；未知 / 损坏版本安全拒绝。刷新自动恢复应为否。
- **信任边界理解**：用户能否准确说明本地文件、内存、无数据库写入、用户声明与平台核实差异，及接受改写不构成认证。

记录模板为：研究版本 / 材料 SHA / 匿名场次 / 任务 / 起止及中断 / 完成状态 / 操作与帮助计数 / 原话观察 / 对应截图引用 / 安全事件 / 待复核问题。结果值本轮均为空；不创建假参与者来填表。

## 分析与停止标准

P0 包括编造被当成认证、隐私外发或意外写入；P1 包括核心任务失败、来源不一致和重要恢复丢失；P2 为明显效率、打印品质或理解问题；P3 为一般交互改进。保留分母、未完成、退出、故障和反例，分别报告自动合同结果、合成可用性观察与将来的真实人类研究结果。

真实模型与真实用户研究必须分别批准。人工参考审核先记录 `agree` / `dispute` / `uncertain` 和理由；工具不能验证审核者自然人身份或独立性，更不能自动晋升为金标准。发现硬性事实问题或用户持续误认认证时应停止扩大实验，而非用满意度平均分覆盖。

目前可报告的只有：脚本已准备、公开合成旅程和浏览器测试的实际证据。不能报告“用户喜欢”“节省 X 分钟”“模型准确率达标”或“正式 MVP 已上线”。所有 G4、T2/T3、共享 CO 键域、R03、D4/D5、D6 剩余、D8 继续 BLOCK。
