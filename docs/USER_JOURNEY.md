# 典型用户路径（设计稿）

## 路径 A：已经有简历

1. 上传简历或粘贴文本。
2. AI 抽取经历，用户检查关键事实。
3. 粘贴 JD，得到岗位要求和差距解释。
4. 生成岗位专属简历，对比改写原因。
5. 用户修改、预览、导出。
6. 可选进入快速复习：3 题 → 简要复盘。

**首次价值点**：同一条真实经历针对不同岗位可以得到更有针对性但不失真的表达。

## 路径 B：还没有像样的简历

1. 输入学习背景、求职方向和一个模糊经历关键词。
2. AI 每轮只问 1–2 个关键问题，记录“确定/待核实”。
3. 展示「原始描述 → 经确认的事实 → 专业表达」。
4. 保存经历卡并生成基础简历，按需进入 JD 定制。

**首次价值点**：用户发现原本以为“不值得写”的真实工作能被组织成清楚的项目描述。

## 路径 C：已经有目标岗位

1. 粘贴目标 JD。
2. 先解释岗位核心要求和可能的硬门槛。
3. 再让用户导入简历或回答最重要的经历问题。
4. 形成申请策略，并选择是否生成定制简历。

**首次价值点**：用户得到具体行动建议，而非只得到一个没有依据的匹配百分比。

## 共通交互规则

- 用户可跳过复习训练，不影响生成/导出简历。
- 问题自适应，不因用户不记得就无限追问。
- 已有经历档案可以复用，避免重复填写。
- 与事实相关的新增陈述必须由用户确认后才能写入简历。
