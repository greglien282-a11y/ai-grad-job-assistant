# C-1C：风险明确的单次受控实验可行性（未批准、未实现）

适用前提：供应商不能提供可审计的完整计费上界，而负责人仍希望讨论一次完全合成探针。此文仅用于决策，**不创建可执行入口，不改变上界门禁、预算或零授权状态**。

## 能回答什么，不能证明什么

一次 S03/b 可以未来观察该次响应版本、结构、usage、耗时及最终扣账，帮助确认实际账户币种/价格和后续合同差异。它不能证明未来请求/失败请求的硬费用上界、模型权重固定、隐私零留存或供应商端绝对一次执行。max_tokens只限生成；1M容量、余额、充值10元或“只调用一次”不等于已证明的最大人民币损失。

目前条件算术约为 CNY2.002048/2.099200 或 USD0.3003072/0.3148800（取决于未证实C含义），没有获批汇率/税费。这只是基于假设的保守示例，**不是风险损失封顶**。若存在未计入收费、计数差异、错误计费、异步扣账、价格变化或基础设施补发，实际可能超过假定预留；现有证据不能硬性界定该差额。赠金、余额耗尽及移除支付方式是否构成供应商硬限制也未获证明。

## 单独决策所需条件

- 负责人明确选择是否接受“没有数学/合同硬上界”的残余费用风险；不能用接受风险的签名重新命名为verified token certificate，也不能填写虚假的已验证输入数。
- 单独讨论风险额度、异常账单责任和供应商账户是否有可证明的外部消费硬限额。不能保证损失不超某金额时必须直说；若负责人要求绝对不超预算，则该替代方案不可执行，只能继续等待供应商证据。
- 独立技术/安全评审一个**与当前硬保证路径分离**的实验政策。它需要新的风险模型、账本状态/冻结/核账方案和明确授权合同，不能修改一个布尔值、伪造owner_attested、调用现有offline入口带真实Key或绕过PaidControl。
- 仍须先完成原币账户/价格、固定合成SHA、独立生产broker/LOGIN、中央池、一次交接、无重试/回退、密钥安全及未知费用占用设计。实验中发生任何不确定结果立即停止并人工核账，不进行第二次补调。
- 外发严格只限固定S03/b，执行/核账时间窗和人员、密钥引用、余额只读许可、实际账单证据及超额冻结都要另外批准。真实资料仍禁止。

## 当前可行性结论

作为未来的风险取舍议题可讨论；**当前不可执行**。它不是通过少量实际测试“证明”原门禁，也不是要求负责人现在提供Key或消费授权。未经单独的设计、代码审查和明示授权，不开发绕过路径，不调用供应商。真实次数0、费用0；当前批准总额0元。
