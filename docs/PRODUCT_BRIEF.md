# 公开版产品需求摘要（目标版本 V0.3）

> 2026-10-28 校准：Pathwise 希望帮助应届生用已有真实材料制作可核对的一岗一简历。现有 M2 是已合并、默认关闭的本地开发预览；尚未面向真实用户上线，不等于正式最小可用产品已发布。

## 现在能够演示什么

在显式启用的开发环境中，用户可从粘贴、TXT / MD、可选择文本 PDF / DOCX 开始，先核对解析文本、顺序和引用，再为同一材料建立多个岗位草稿。现有实现提供确定性 JD 字面关联、用户能力自评、选择 / 排序 / 编辑、简历输出与来源审查、两种版式、原生打印 / PDF，以及主动下载 / 导入严格版本化草稿和岗位独立三题复习。

处理默认只在浏览器内存；没有自动上传、遥测、自动保存或远端账户同步。刷新后须主动导入已下载文件。下载包含原文、用户填写的联系方式、草稿和回答，须自行妥善保管。生产构建不能访问两个实验室。

PDF / DOCX 提取可能遗漏或乱序，必须人工核对。引用是相对解析文本快照的 Unicode code-point 区间，不是原文件字节位置或真实性证明。扫描件 / OCR、旧 DOC 和任意版式无损解析尚不支持。

## 两种内容资格必须分开

正式受限经历预览沿用事实、审核和来源合同：未经核实的改写不能自动进入可信打印正文。用户确认表示用户自述，材料支持也不等于平台独立认证。

本地简历草稿是另一种用途：用户可以保留和修改自己的文字，输出明确为未经平台核实的用户自述。导入、编辑、接受建议、恢复 JSON 或回答复习题均不能生成已认证 FactV3。团队、计划、否定、未知和拒绝边界不能经建议或视图切换变成已完成个人成果；现有精确文本保护不等于已解决 R03 语义复活。

## F01 · 可追溯经历库（部分工程基础已有）

目标输入为旧简历、自由文本和用户回答，输出教育、课程、项目、技能等事实及完整来源。legacy 建档、历史和审核已有代码；分类矩阵和 typed 只读合同已有隔离验证。正式 typed writer、分类选择依据持久化、CO3 与正式产品接入仍未准入。本地草稿不是该数据库的替代认证入口。

## F02 · AI 经历挖掘（真实模型能力未验证）

目标是少量高价值问题帮助回忆实际工作、个人职责和可验证结果，避免诱导虚假记忆。已有合成合同与 Mock 研究不代表真实 Provider 的效果、费用、隐私或生产权限得到验证；本轮不调用真实模型。

## F03 · 岗位策略（确定性基线已运行）

现有预览区分必备 / 加分 / 待核实条件、字面相关、证据不足与用户明确自评的能力缺口，展示命中词、来源片段及 JD 原句。关键词相同不证明熟练度、语义理解或已证实匹配。没有伪精确匹配率，不能自动补造技能、部署、数字、学历或个人贡献。

M2.5 新增的离线建议候选须经过严格来源合同和人工决定；Mock 的改写示例不等于可直接采用的事实。生成参考标注均先为 `draft_unreviewed`，未独立人工审核前不发布模型准确率或事实错误率。

## F04 · 一岗一简历（本地体验已运行，正式产品待验证）

突出与岗位有关的已有内容，解释修改、保留原文、支持撤销与恢复；不强行改写。输出、来源核对和用户修改要清楚分开。现有本地多岗位、打印和恢复具备可运行证据，但没有正式账户、数据库写入、真实 AI 定制或生产上线保障。

## F05 · 掌握这份简历（本地三题已运行）

快速复习绑定当前岗位、所选条目和原始经历；允许跳过 / 结束，能力缺口应转为学习准备，不能生成虚构项目讲述。更完整的标准模拟和深度追问仍是后续目标。详见 [面试模式设计](INTERVIEW_MODES.md)。

## 验证目标与未解决事项

首次可见价值、单岗完成用时、第二岗位减少重复输入、建议理解、错误改写识别、打印 / 恢复成功率均需真实研究。此前“争取 10–15 分钟”的设想是待验证目标，不是已测得结果。本轮只准备合成任务脚本，无招募、真实参与者或满意度数据。

G4、T2/T3、共享 CO 键域、R03 全入口语义防复活、D4/D5、D6 剩余、D8 及正式 typed writer / CO3 均继续 BLOCK。M2.5 不授权真实付费请求、生产数据库 / 迁移 / ACL、部署或开放真实用户。

完整范围、研究和审批边界见 [路线图](ROADMAP.md)、[M2.5 说明](M25_AI_QUALITY_AND_SUGGESTIONS.md)、[未来模型试验审批包](M25_PROVIDER_APPROVAL.md)。

全网职位聚合、自动投递、复杂支付体系和无人监督操作不在当前最小体验中强制实现。
