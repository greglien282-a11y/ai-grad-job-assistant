# 路径 B：02 回答与核对体验调整

基线 `0c887c1c54204caea2f011affd4f0558fa930939`。仅调整已有工作区呈现；首页、01 描述表单、03 成果视图、后端合同和 PR #21/#22 的实验成果均不修改。

## 操作路径

之前：历史原话、追问、问题管理按钮和会话管理同时出现，回答关联只在框下用短句说明；所有事实按原顺序显示。

现在：

1. 当前完成轮次的 1–2 题保持展开、加大题目字号；历史描述与历史追问可展开追溯。问题的跳过、纠正、隐藏和删除收在“问题选项”中，不删除历史数据。
2. 当前问题提供“回答这题”：用户点击或键盘激活后显式关联并聚焦原回答框，不提交、不改草稿；可勾选两题。关联正文在回答框上方显示，默认不选即自由补充。重复点击同一题不会取消关联，清除关联不清空回答。问题版本移入管理选项，删除后仍保留只读版本。
3. “审核待确认事实”切换窄屏面板并聚焦、滚动到审核区。待确认卡片排前，保留原始编号和 React key；状态变化时不重建编辑草稿。确认、编辑、拒绝、记忆状态、材料核实、来源及历史仍使用原 FactCard。
4. 已确认数量说明何时可以阅读 03；未确认时也可以访问空状态。整理正文仍只由现有后端 experience-summary 提供，不能包含 pending/rejected。
5. 会话管理及确认面板移到工作区底部，技术备份仍折叠。恢复失败警告和只读恢复操作留在顶部；恢复成功前管理操作仍被原守卫阻止。

## 组件边界

- `DiscoveryWorkbench`：布局、面板聚焦、现有管理确认；没有增加数据写入路径。
- `Conversation`：以稳定的回合 key 折叠历史，最新用户回答及最新完成轮次仍可见；失败轮次不会把上一组可回答问题完全藏起。
- `QuestionCard`：只折叠管理工具，纠正草稿和删除确认继续保留。
- 新 `AnswerComposer`：抽出原输入表单，沿用 `useDiscovery` 的提交/恢复/关联逻辑、IME 和快捷键判断。
- 新 `FactReview`：仅排序视图，保持编号、key 和原 mutation 回调。
- `FactCard`：仅增加状态 data 属性供样式使用。
- PR #23 保留原 useDiscovery；本轮交互状态适配在该 Hook 中增加请求阶段、冲突/未知结果保守守卫及草稿保护。API 客户端、幂等格式、生产后端与数据库不修改，详见 [交互状态合同](DISCOVERY_INTERACTION_STATES.md)。

## 人工验收重点

- 桌面从首页进入路径 B，仅输入合成经历；能否迅速找到当前题目、理解勾选与自由补充。
- 390px/320px 和浏览器原生 200% 缩放：选题、键盘焦点、触控按钮、切换审核、确认及前往 03；正文和输入不小于 16px，无横向溢出。
- 编辑中的事实在另一条事实确认后移动位置，草稿仍在；切换 03 并返回也保留草稿。
- 网络断开/版本冲突时，顶部恢复说明可见；不会重复写入，结束/删除仍禁用。停止/结束/删除仍需原有二次确认。
- 历史展开后能查问题版本、回答关联、原文、材料依据；技术 JSON 明确是备份。

## 后续真实 AI 接入仍缺少什么

正式用户流仍为零费用 ScriptedProvider；ContextFakeProvider 只是测试工具。本轮没有把离线提示词、单次探针或模型适配器接到工作台。

后续需独立审查、授权：真实 Provider 的正式运行接线、模型/版本/区域配置、合成评测与留出评测、质量与延迟验证、隐私和外发范围、调用预算和费用对账、密钥权限、失败/未知结果恢复，以及提示词版本和来源校验的一致性。不能从单次已核销实验推断工作台已具备真实自适应能力。
